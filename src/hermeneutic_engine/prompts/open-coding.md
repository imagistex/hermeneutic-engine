Method: initial (open) coding, in the constructivist grounded theory tradition.

You will receive a batch of units. Each has an ID, some context (the page it appeared on, when it first appeared, the name it was saved under) and its text. Code each unit on its own terms.

What a code is here:

- A code names what is happening or being done in a passage. Prefer gerunds for actions and processes: "asking for a signal", not "signals".
- An in vivo code uses the writers' own words as its name, because their wording carries meaning a paraphrase would lose. Mark it `in_vivo`. The name must appear word for word in the unit.
- An analytic code is your own short label for something the writers do not name themselves. Mark it `analytic`.

How to code:

- Stay close to the text. Code what is said and done, not what you suppose lies behind it.
- Do not bring in a theory or a moral verdict, and do not decide in advance what this material is a case of.
- There is no quota. A unit may get several codes, one, or none. Leave out anything that would be padding.
- Reuse a code name within this batch when the same thing recurs. Make a new one when it differs, even slightly, and say how in the note.
- Notice vocabulary that seems particular to these writers (terms of art, role names, set phrases) and code it in vivo.
- Give each code a one-sentence definition that would let another reader apply it.
- Use the note for doubt, for an alternative you considered, or for how this code differs from a neighbour. Leave it empty when you have nothing to add.

In `batch_memo`, write three to six sentences on what struck you across the batch: patterns, surprises, things you could not make sense of. Do not summarise the units one by one.
